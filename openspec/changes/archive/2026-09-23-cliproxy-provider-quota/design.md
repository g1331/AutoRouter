# Design

## Context

见 [proposal.md](./proposal.md)。当前 `cliproxy-account-usage-service` 只读取 `/auth-files` 的进程内请求统计和被动配额信号；账号详情把这些信号放在底部，不能给出供应商当前剩余比例。官方管理中心的 Codex、Claude 额度页以 `auth_index` 调用 CLIProxyAPI 管理端的 `POST /api-call`，再分别请求固定的供应商用量地址。AutoRouter 已有管理目标解析和请求客户端，可复用其鉴权、超时与错误映射。

## Goals / Non-Goals

**Goals:** 只读获取 Codex 与 Claude 的主要额度窗口；在账号行提供明确入口，在详情顶部展示剩余比例和重置时间；把缺失、失败与不支持区分清楚。

**Non-Goals:** 不批量探测全部账号，不消费 Codex 重置积分，不实现供应商付费余额或不可验证的 Gemini 额度，不持久化额度快照。

## Decisions

### 按账号查询，服务器投影

新增管理员单账号 GET 接口。服务端先读取该实例的 `/auth-files`，按文件名找到当前认证索引和账号类型，再向 CLIProxyAPI 发送一次固定地址的只读 `/api-call`：Codex 查询 `chatgpt.com/backend-api/wham/usage`；Claude 查询 `api.anthropic.com/api/oauth/usage`。Token 替换由 CLIProxyAPI 完成。调用方不能提交目标 URL、请求头或认证索引；服务端只投影窗口标识、剩余比例、重置时间与读取时间，绝不回传原始响应。

选择按需查询而非打开页面时批量刷新：供应商调用可能较慢、限流且部分账号没有认证索引；单账号查询使失败作用域明确。当前请求统计接口和被动观测保留原有语义。

```text
管理员打开账号详情
  → AutoRouter Admin 鉴权
  → 实例管理连接 → CLIProxyAPI /auth-files
  → 精确匹配账号文件名与 auth_index
  → CLIProxyAPI /api-call → 固定供应商额度地址
  → AutoRouter 裁剪并归一化窗口 → 账号详情
```

### 可读额度窗口

Codex 读取主要与次要限额窗口及可用的代码审查窗口；Claude 读取五小时和供应商实际返回的七天窗口。剩余比例由供应商已用百分比计算，数值零保留为零，缺失或无效字段显示未知。重置时间接受供应商返回的时间戳或重置后秒数；无有效时间则不猜测。供应商非成功状态与无法解析的响应作为独立查询失败，不遮蔽账号目录。

### 工作台呈现

账号表的配额列改为“供应商额度”：受支持账号展示“查看额度”，其他账号明确标为“不支持”或“已停用”。点击与账号行“查看详情”共用详情弹窗，打开后只查该账号。详情顶部展示额度窗口和刷新按钮；下方保留请求统计、被动配额观测及账号元数据，标题明确区分数据来源。

```text
桌面账号行：账号文件 / 请求统计 / 供应商额度：查看额度 / 操作
手机账号行：账号文件 / 请求统计 + 查看额度 / 操作

账号详情：
┌ 供应商额度                         刷新额度 ┐
│ 主要窗口                  68% 剩余          │
│ ███████████░░░░░  ·  16:00 重置             │
│ 次要窗口                  42% 剩余          │
│ ███████░░░░░░░░░  ·  周五重置               │
├ 请求统计：成功 / 失败 ──────────────────────┤
│ 账号资料、近期请求、代理被动观测             │
└──────────────────────────────────────────────┘
```

视觉层级以真实剩余额度优先：窗口用无卡片分隔行、数字与单色进度条共同表达剩余比例；未知值不绘制进度条。请求计数与代理被动观测保留但不混作余额。窄屏采用纵向窗口行和可换行时间，增加弹窗可视高度以露出请求统计。

## Risks / Trade-offs

- [供应商或 CLIProxyAPI 版本改变响应形态] → 只识别已知字段，空窗口与错误分开显示，加入固定响应测试。
- [认证索引缺失、Token 过期、供应商限流] → 按账号查询并提供重试；不自动批量探测。
- [供应商响应携带敏感字段] → 服务端白名单投影，错误消息不包含上游 body；加入安全测试。
- [额度查询影响账号管理] → 独立查询和 UI 状态，原账号目录、请求统计接口不依赖其成功。

## Migration Plan

无需数据库迁移。先加入服务和接口，再接入账号详情与列表、补两套文案和测试。回滚这些代码即可恢复原界面，请求统计数据与账号缓存不变。
