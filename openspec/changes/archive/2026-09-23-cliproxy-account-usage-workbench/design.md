## Context

见 [proposal.md](./proposal.md)。当前 `cliproxy-auth-account-service` 将 `auth-files` 同步到本地账号缓存，但只保留目录与模型信息。`GET /auth-files` 在 CLIProxyAPI v7.3.12 可返回 `observed_at`、进程内 `success`/`failed`、20 个十分钟的 `recent_requests` 分桶，以及被动采集的 `quota.signals` 和 `quota.observed_at`；当运行时管理器不可用时仅返回磁盘字段。现有页面把实例表、账号表、关联上游与日志四块面板纵向堆叠；已在 1440px 和 390px 截图检查，窄屏实例与账号表的右侧列被裁切。

## Goals / Non-Goals

**Goals:** 以只读请求获取当前账号用量，显示每个字段是否可用与读取时间；让实例选择、账号状态和用量在首屏具有清楚的视觉层级，并保留全部已有管理操作。

**Non-Goals:** 不把 CLIProxyAPI 进程内计数当作持久账本；不调用会弹出记录的 `usage-queue`；不向供应商主动发起配额探测，也不改变账号路由与计费。

## Decisions

### 独立只读用量链路

新增 `GET /api/admin/cliproxy/instances/:id/auth-accounts/usage`，服务端按既有管理密钥读取 `auth-files` 并返回必要字段。账号目录仍从本地缓存加载。这样用量失败只影响用量区域，账号操作仍可使用；与把易变化计数写进账号缓存相比，避免数据库迁移、过期快照和同步频率耦合。沿用现有 `requireAdmin` 与 CLIProxy 错误映射。

响应提供 `fetched_at`（AutoRouter 完成读取的时间）、可选 `observed_at`（CLIProxy 返回的观测时间）、逐账号 `success`、`failed`、`recent_requests` 和 `quota`。缺失值为 `null`，零保留为 `0`。近期分桶限定为上游已知的时间标签与非负计数；配额只取 `quota.signals` 中名称含用量／重置语义、值为短数字或时间的项，避免透传认证文件或任意管理字段。

### 主工作区和次级视图

单实例时，桌面将实例选择压成工作区上方的横向栏，工作区按侧栏之外的可用宽度展开，使用固定页面边距，不额外限制在窄容器内；新增实例操作放在页头。多实例且视口至少 1280px 时，使用约 14rem 的独立实例栏与弹性账号工作区。更窄的视口纵向排列两个区域，避免实例栏挤压账号表。实例栏按内容高度结束，不随账号工作区拉伸。实例选中态以窄边框表达，避免大面积着色。账号面板上方展示数据含义、读取时间、刷新状态，账号行以文件名／邮箱、状态和请求计数为主，更多信息与近期分桶、配额信号在详情中展开。次级视图以“账号”“关联上游”“实例日志”切换，只有可见视图装载其数据。实例项保留启停与操作菜单，账号项保留模型、下载、启停、编辑、映射与删除入口。

## Risks / Trade-offs

- [CLIProxy 进程重启使累计计数归零] → 在界面注明计数范围，不计算跨重启趋势。
- [旧版或磁盘回退响应缺少字段] → 用 `null` 标注未知，不显示假零或假额度。
- [上游 `quota.signals` 字段形态随提供者变化] → 保留短的可识别观测键值，在详情中按原键名显示，不解释成统一余额。
- [工作区隐藏次级视图可能影响旧页面测试] → 更新直接依赖页面结构的 E2E 断言，覆盖切换与窄屏操作。

## Migration Plan

无数据迁移。先加入只读接口及测试，再替换页面布局并验证；回滚代码即可恢复旧页面，不影响账号缓存。
