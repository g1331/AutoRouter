# 上游响应模型不一致告警设计

## Context

动机见 proposal.md，行为契约见 `specs/request-log-workbench/spec.md`。代理的 JSON 与 SSE 解析已经提取用量、等级并原样透传；成功结算分别位于非流式和流式生命周期。请求日志的 `routing_decision` 是 JSON 文本，管理员 API 原样传递而会员 API 已清空此对象。共用日志表同时支持桌面行与移动卡片。

## Goals / Non-Goals

**目标：** 在既有解析路径低成本采集响应模型，最终成功结算时对照 `terminal.resolvedModel` 判定，保留有意重定向与上游静默换模的区别；管理端清楚可见，历史日志与会员页安全兼容。

**非目标：** 不根据响应内容重试或更换上游；不把原始别名、CLIProxyAPI 账号前缀或 `(path-based)` 视为预期模型；不改变计费、客户端响应和数据库结构。

## Decisions

1. **响应采集留在 `proxy-client.ts` 现有 JSON/SSE 解析路径。** 顺序读取顶层 `model`、`response.model`、`message.model`，只接受去空白后非空字符串。直接解析后的值供非流式结果使用；流式回调只保留首个模型和首个不同模型。由于任一预期模型若与某事件不同，两个不同值中至少一个与其不同，最多两值即可判定，不缓存整个流；不重新解码响应字节。替代方案是日志层二次解析输出流，会增加内存与改变流时序，故不采用。
2. **最终成功结算才决定告警。** 两种生命周期从最终请求 `resolvedModel` 比较；流式优先记录第一个与其不相等的值。仅 2xx、有非空响应模型且预期模型存在时才可能为真，一次结算只 `log.warn` 一次。失败、断流、取消路径不写入诊断字段。替代方案在每个事件即时告警会产生重复或最终失败的误报。
3. **复用 `RoutingDecisionLog` 可选字段。** `response_model` 与 `model_mismatch` 序列化到现有 `request_logs.routing_decision`，维持 `request_logs.model`、价格快照与历史记录不变。会员数据净化已经清除此对象；无需迁移。替代方案新列会扩大双方言迁移与日志 API 维护面积。
4. **告警与意图分开显示。** `model_mismatch === true` 是 UI 唯一触发条件，桌面状态列与移动摘要为紧凑警示徽标，详情响应步骤分开展示两个值；原重定向 info 标记保持原位。中英文文案通过 `logs` 命名空间本地化。

### 管理界面布局示意

```text
桌面（lg+，状态列）
┌────────┬──────────────────┬─────────────────────┐
│ 时间   │ 模型             │ 状态                │
│ 14:23  │ gpt-4            │ 200 [重试 1] [模型不符 ⚠] │
└────────┴──────────────────┴─────────────────────┘
                                  │ 点击展开
                                  ▼
请求旅程：请求 → 路由 → 上游响应
                        预期模型       gpt-4
                        上游返回模型   gpt-3.5 ⚠

移动（摘要卡片，徽标可换行且不挤压模型名称）
┌───────────────────────────────┐
│ gpt-4      200 [模型不符 ⚠]   │
│ 14:23      上游名称 · 耗时     │
└───────────────────────────────┘
```

视觉层级：状态数字为主；琥珀色紧凑警告徽标为次，悬浮/聚焦解释“预期 → 返回”；详情展示可换行的完整模型名。匹配、无响应模型和旧日志不出现警示。

### 数据路径

```text
上游 JSON / SSE → 原有解析 + 模型提取 → 最终成功结算
                                        ├─ 原始响应原样返回
                                        ├─ routing_decision(JSON) → 管理端日志 → 警告徽标/详情
                                        └─ 会员日志净化（移除 routing_decision）
```

## Risks / Trade-offs

- [上游不提供模型或非 JSON 事件] → 无法可靠比较，保留原响应且不告警。
- [SSE 事件中多个不同声明] → 只保存最多两个不同值，足以发现与固定预期模型的任意差异；展示首个不同值而非完整集合。
- [历史日志缺字段] → 可选字段，UI 严格检查 `true`，不会误报。
- [模型名过长] → 徽标紧凑、详情内容换行，桌面与窄屏实际检查。

## Migration Plan

部署无需迁移，回滚代码即可停止采集与展示；已有可选 JSON 字段不会影响旧版日志读取。
