# 上游响应模型不一致告警

## Why

代理现仅记录经规则解析的请求模型，未比较上游成功响应声明的模型；上游静默换用其他模型时，管理员无法从请求日志发现差异。需要非阻断的诊断提示，同时保持客户端响应、路由和计费语义不变。

## What Changes

- 从成功的 JSON 与 SSE 上游响应中提取非空模型标识，支持顶层 `model`、`response.model` 与 `message.model`。
- 在成功请求的既有路由决策 JSON 中保存响应模型及是否与最终解析的请求模型不一致；真正不一致时仅写一条结构化警告。
- 管理端桌面与移动日志摘要显示警告徽标，详情显示预期与返回模型；保留有意模型重定向的独立信息标记。
- 补充代理、生命周期、界面与端到端行为验证；不新增数据库迁移、不修改下游响应，也不向会员开放上游诊断字段。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `request-log-workbench`：成功上游响应与最终请求模型不一致时的日志诊断、管理端展示及会员隔离。

## Impact

涉及代理响应采集、成功结算时的路由决策日志、管理端共用日志组件及中英文翻译。既有 `request_logs.routing_decision` JSON 可承载可选字段，无数据库结构变更；历史记录继续兼容。
