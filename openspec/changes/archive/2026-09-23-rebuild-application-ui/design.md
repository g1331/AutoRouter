### 规格冲突的处理

本变更通过增量规格明确替换：旧的固定主题描述、只允许四种动效、强制背景氛围、强制头卡与描述，以及成员导航仅三项的要求。现有三档数字排印规定 Saira／mono／sans，当前全局字体也如此，因此保留该规则并消除基础规格中旧的 DIN 描述。`--vr-*` 真源、状态色、圆角白名单、AA 对比度与现有领域功能契约继续有效。已存在的图表组合、sparkline、告警、LED 状态及布局契约不因本次减饰而删除。

## Goals / Non-Goals

**设计目标：**

- 用一套共享基础承载概览、密集列表、长配置和短表单；在动手迁移任一页面前确定完整结构。
- 每页由“实际业务内容 + 状态 + 关联操作”组成，不出现介绍设计本身的产品文案。
- 将双向、可中断的展开收起和页面切换作为明确体验目标，消除仅入场有动画、退出硬消失及布局瞬间跳变。
- 让共享变更能以可验证的小批次落地，最终覆盖所有页面，而非形成长期并行的新旧组件体系。

**设计边界：**

- 复用现有 React、UI 原语、表单、查询与图表设施。不新增通用页面配置引擎、组件库、字体服务或状态管理层。
- 不把页面样式改版扩大为后端重构、价格与权限变更。接口没有的指标不显示，不用模拟数据填满正式页面。
- 不要求每个指标、每张卡片都有说明、图标或动画。文案只承担业务职责。

## Decisions

### 1. 公共基础先接受四类内容检验

同时用管理概览 P02、请求记录 P08、上游详情 P07 和密钥创建操作 P04 检验共享结构，覆盖统计、密集行、长配置及表单成功／失败。采用这一组内容是因为源码已体现这些不同的约束。放弃只由成员概览决定所有布局的方式，也不先做空组件展示页。

实现沿用 `AppShell`、`PageShell`、`PageHeader`、`Topbar`。`PageShell` 既有宽度选项足以承载常规、紧凑和宽内容，优先复用；必要的标题操作能力通过现有 props 小幅调整，不为每个页面新增一套外壳。迁移后的页面不重复手写等价容器。

桌面固定侧栏、移动底部导航与现有主滚动容器继续使用。页面标题在桌面和移动端均明确可见：页面内容头部承载主标题和主要动作，顶栏负责当前位置／返回关系和角色适用的运行信息，避免重复两个同样的视觉主标题。长配置的对象摘要和分区导航可保持可见；不强制全部页头吸顶。

### 2. 视觉方向采用品牌连续性与功能分层

以下是本提案采用的设计默认值，不是已经通过运行验收的结论：暗色使用接近落地页的低饱和近黑基底、柔和浅色正文与暖橙强调；亮色采用中性浅底和能达标的深暖色强调，不用大面积黄底。最终色值在既有 `--vr-*` 令牌中确定，以对比度和实际页面验收为准。

沿用现有字体资源与数字三档契约，不新增字体下载。标题层级通过字号、字重与间距建立；费用、延迟和 Token 保持等宽数字对齐。卡片只用于确有边界的独立信息或操作组；列表和配置分区优先以间距、细线分隔。仍需要图标方块时使用 `IconBox`，不为了满足形式给每段内容都放图标。

在既有状态反馈与容器过渡基础上补全细腻的双向切换；不将落地页粒子、整屏吸附或模拟启动移植到应用。公共令牌可能影响公开页，落地页必须做回归而非顺带改版。

### 2.1 全站可感知体验调查与处置矩阵

用户列举的展开收起和页面切换不是范围边界。本次源码调查覆盖基础控件、布局／导航、查询与 mutation、图表、复制结果、排序与多入口偏好；按“触发 → 即时反馈 → 处理中 → 内容变化 → 结果 → 再次操作／返回”检查完整链条。体验优化包含响应、稳定性和可达性，增加动画只是实现手段之一。

调查时浏览器没有打开的应用标签页，本地 3000／3331 未监听；本轮没有运行页面或触发真实写操作。以下区分源码事实与待动态验证的问题，不能把潜在卡顿、闪烁或遮挡描述为已经复现。实施时对每页实际触点记录“已优化／已验证保留／不适用及理由”，不是再做一次无目标的全仓探索。

### 2.2 切换动效的覆盖与节奏

当前源码存在可复用基础与明确缺口：`use-container-morph.ts` 使用原生 View Transitions 连接触发源与弹窗，`DialogContent` 已避免与默认进退动画叠加；`AppShell` 的路由 key 主要触发 `.rise-stagger` 新页进场；日志详情的一处 `section.expanded ? ... : null` 仅应用进场类，关闭时直接移除。现有能力存在不代表双向过程、中断和异步高度已经通过验证。

| 交互                         | 期望过程                                                       | 建议初始节奏                  | 核对场景                                     |
| ---------------------------- | -------------------------------------------------------------- | ----------------------------- | -------------------------------------------- |
| 日志详情、折叠分区、高级筛选 | 容器空间与内容一起展开；关闭平顺收回，图标同步                 | 180–280ms，减速进入、收起略快 | 长内容、异步增高、反复点击、同时展开多个对象 |
| 弹窗、关联操作               | 沿用有明确触发源的容器过渡；背景遮罩同步淡入淡出，关闭回到来源 | 220–320ms，柔和收束           | 立即关闭、连续换对象、触发源删除或移出视口   |
| 同级页面                     | 稳定导航与顶栏，只让内容区轻微淡出／淡入并短距离衔接           | 180–260ms，约 4–8px 位移      | 快速切页、加载／错误、不同滚动位置           |
| 列表进入详情与返回           | 同一组轻量前进／返回关系，避免内容大幅飞入                     | 200–300ms                     | 浏览器前后退、直接深链接、滚动恢复           |
| 标签、实例分区、编辑／只读   | 选中反馈立即发生，内容短暂衔接；必要时协调容器高度             | 140–220ms                     | 快速选择、表单焦点、旧内容卸载               |
| 异步区块                     | 骨架／内容或真实错误自然衔接；保留已有数据的刷新不重播进场     | 120–200ms                     | 慢请求、部分失败、动态提示行、旧数据刷新     |

时长和位移是实施调校起点，不是每个组件必须等待的固定时延。进入与退出的时序必须都成立，整体手感柔和但不拖慢操作；不对每张卡片叠加弹跳、缩放或长串瀑布。动效方向表达对象关系，无层级的同级导航不按菜单顺序假造前进／后退。

### 2.3 最小实现路径与生命周期

1. 优先复用既有 CSS 动效令牌、Radix 进退状态和 `useContainerMorph`，简单透明度／位移用 CSS；展开高度使用真实布局方案，避免任意 `max-height` 上限与整块文本缩放。需要控制动态尺寸和反向接续时，局部使用原生动画能力或已经安装的 GSAP，不新增动画库。
2. 对条件卸载的内容协调退出存在期：业务开关状态立即更新，视觉节点在短暂退出后释放；收起时立即移出可交互范围，若焦点位于其中先恢复至触发器。重新展开应取消旧的释放任务，从当前状态接续，不能在新内容出现后由旧回调将其删除。减少动态效果时直接到终态。
3. 动态高度测量只作用于需要的容器，读写分离；仅在内容变化时更新目标，卸载清理监听、动画与临时样式。高频实时列表不对所有历史行同时做布局动画。
4. 页面过渡属于现有导航／壳层边界，优先使用能与实际路由提交衔接的浏览器过渡；不能把只适用于同步状态的 `flushSync(apply)` 原样当成异步路由完成。需要验证目标页面提交、旧快照释放和中断的时序，不冻结 Next.js 路由上下文，不双挂载业务页面，也不以 `setTimeout` 延迟导航来凑退出动画。
5. 旧内容可由非交互快照参与退出，新页面／其加载状态按真实路由提交出现；壳层、实时条与固定导航不参与整页位移。无增强能力时采用基础内容切换，不依赖实验性路由接口或新增框架。认证失效、权限变化与登出优先清除受保护内容，不保留其退出快照。
6. 新动作优先于旧动画：取消或重定向旧视觉过渡，不重复业务回调。现有 morph 的临时命名、重复调用、源节点消失与卸载需要在扩展时验证；降级保留正确操作，不吞掉业务错误。与弹窗默认动画只保留一条视觉路径，避免叠加两次位移。
7. 为含 sticky、fixed 或 portal 的祖先设置 transform 前核对定位上下文；不能用全页缩放破坏表格吸顶或弹窗位置。减少动态效果和动画能力缺失采用统一规则，各页不自行维护另一套降级状态。

每页迁移时对照上述矩阵完成适用的动效，组件展开、弹窗、页内切换与异步内容都属于该页的完成范围；不是最后统一加一个淡入类。具体 API 使用须以当前安装版本和目标浏览器的实际验证为准，本规划不声称原生路由过渡已实现。

### 5. 文案审查是页面验收的一部分

每段文字必须回答：它标识了哪个业务对象、说明了什么真实事实、指导了哪一步操作或解释了什么结果？回答不出则移除。标题不自动附说明；装饰性英文不因看起来像仪表盘而保留。翻译 key 可以沿用，界面文本不得出现开发与设计术语；协议名、状态码、模型和日志中的实际技术字段按业务需要保留。

| 禁止作为产品文案                     | 可用的业务表达                           |
| ------------------------------------ | ---------------------------------------- |
| “通过清晰的信息层级呈现核心指标”     | “本月费用”，注明真实时间口径             |
| “全新布局，高效管理您的密钥”         | “API Key”“创建密钥”                      |
| “这里展示您的使用趋势”               | “请求量”和范围控件                       |
| “系统就绪”“NETWORK ONLINE”（无检测） | 实际请求的处理中、失败、完成状态         |
| “空状态设计”“卡片区”                 | “暂无请求记录”或“没有符合筛选条件的记录” |

扫描已知违禁短语能发现遗漏，但不能代替逐页阅读，也不建立误伤业务日志的全局关键词黑名单。设计草图与开发说明只留在本变更文件中。

### 6. 查询、保存与导航行为保持原有边界

使用既有查询结果的 loading／fetching／error 分支和 mutation 状态；页面按区块处理结果，不再以 `data ?? 0` 或 `items ?? []` 掩盖错误。旧内容刷新失败时说明状态并保留筛选。先复用现有提示和按钮，只有重复的状态结构确实需要共享时才抽取局部原语，不创建全局状态机。

分区保存继续使用现有 mutation 与校验；失败保留草稿，成功按原有缓存更新方式反馈。不引入自动保存、跨分区事务、额外重试或新的服务端字段。跨页行为仅连接已有入口和参数，实际缺少目标过滤契约的建议不纳入本次功能新增。

| 用户路径                                                 | 本次保证                               | 不隐含新增                               |
| -------------------------------------------------------- | -------------------------------------- | ---------------------------------------- |
| 登录 → 正确角色工作区 → 密钥创建 → 一次性保存 → 请求查询 | 认证、密钥操作和结果可达，原流程可完成 | 不自动发真实付费请求，不提供虚构接入成功 |
| 管理概览／排行 → 已有请求入口 → 请求详情 → 上游配置      | 原深链接与对象上下文不丢失、诊断可读   | 不要求每个指标新增钻取 API               |
| 用户列表 → 授权／分配密钥 → 个人用量 → 关联请求          | 权限、可见性、用户过滤和历史统计不变   | 不引入跨角色身份切换                     |
| 计费 → 目录／覆盖 → 近期计费与请求详情                   | 数据口径、价格覆盖和既有关联不变       | 不新增账本、余额、退款或重算机制         |
| CLIProxyAPI 实例 → 账号 → 关联上游／池 → 测试与日志      | 选择上下文及已有异步状态保持一致       | 不更换外部服务或真实账户配置             |

## Risks / Trade-offs

- 公共令牌、日志组件、用量图的修改同时影响多个调用方 → 同批验证实际调用方和落地页，避免只验当前页面。
- 密集日志和上游详情可能因字体／留白变化溢出 → 用四类真实内容约束共享规则，移动端按信息优先级重排，不缩小所有文字。
- 标题从桌面顶栏调整到共享页头可能破坏锚点或遮挡 → 保留主滚动容器，核对吸顶偏移、深链接、返回恢复与移动标题。
- 旧规格与当前实现有历史偏差 → 只更新与本次语义直接相关的条目，其余领域规格继续作为回归依据。
- 跨页迁移期间短暂存在旧布局 → 每一批必须功能可用；最终总验收阻止以局部完成代替全部完成，不引入永久主题开关。
- CLIProxyAPI 外部账号授权难以在本地真实复现 → 用既有受控响应验证前端状态，报告没有执行真实第三方授权，禁止冒充外部功能验证通过。
- 页面数量多且像素基线受平台影响 → 分页验收、复用数据与本地工具，最终覆盖全路由；不新增视觉服务依赖。

## Migration Plan

1. 基于本设计先完成公共基础和四类真实页面场景的适配，再迁移登录与设置。
2. 按任务顺序完成密钥、上游、用户管理与用户用量，再完成概览、排行和双角色日志。
3. 完成计费、任务、录制、规则、CLIProxyAPI 和密码页，每页包含其关联操作。
4. 每个阶段完成测试、实际截图和文案审查后勾选对应任务；按阶段进行 Conventional Commit，运行仓库提交钩子，不绕过检查。公共组件与全部必要调用方放在同一安全提交边界内。
5. 最终检查 P01–P21、跨页流程和无旧界面遗漏，完成既有质量门禁；实际部署、push 和远端操作不由本提案自动授权。
6. 无数据迁移。若实现回归，以本变更的阶段提交为恢复单位，在部署环境沿用原版本回退流程；回退公共基础时同时恢复依赖它的页面，禁止修改真实数据库来回退 UI。

### 动态验收补充

静态 visual 测试会关闭动画，因此不能证明动效完成。保留静态截图验布局，另在真实浏览器的桌面／移动视口观察或录制：一次完整展开收起、连续三次快速反向、展开后异步增高、弹窗立即关闭／换对象、同级快速导航、详情返回、慢请求／失败、动画期间卸载，以及 reduced motion／增强能力不可用。复用 `use-container-morph`、`app-shell`、日志与对话框测试检查状态、清理和业务回调，动态浏览器过程检查是否闪烁、跳高、裁切、遮罩残留或焦点失效；不能仅断言动画类名或录下静态终帧。

具体色值、细微间距、折叠阈值和动效节奏由实施中的静态／动态浏览器验证与对比度检查收敛，不改变上述范围和交互契约。
