## Purpose

规定 AutoRouter 登录页、成员自助区和管理后台的完整应用体验，使用户能够在一致的导航、信息层级与操作反馈中完成接入、管理、查询和排障，并确保实际界面只呈现有依据的业务信息，覆盖关联弹窗、详情、错误状态与移动端使用。

## ADDED Requirements

### Requirement: 应用重构必须覆盖全部页面与关联交互

系统 MUST 为下表全部 21 个页面提供一致的应用体验；页面完成范围 MUST 包含其现有弹窗、展开详情、配置表单、分页筛选、状态反馈及移动端交互，MUST NOT 仅迁移初始页面。路径均省略语言前缀，公开落地页与文档站不属于重构范围。

#### Scenario: 全路由迁移验收

- **WHEN** 重构被标记为完成
- **THEN** P01 至 P21 均有页面、关联操作和移动端验收结果，任一未迁移的弹窗或详情 MUST 阻止该页面被标记为完成

#### Scenario: 操作过程中保持一致体验

- **WHEN** 用户从列表创建对象、编辑配置或展开只读详情
- **THEN** 后续界面与起始页面使用一致的标题、控件、状态和关闭反馈，关闭后焦点返回合理的触发位置

### Requirement: 应用文案必须只服务业务判断与操作

系统 MUST 仅展示用于标识对象、说明业务事实、指导操作或解释结果的文案。可见标题、说明、按钮、空态、提示、弹窗与辅助技术可读文案 MUST NOT 包含设计语言、布局讲解、开发过程说明、无信息量的自我宣传或装饰性英文标签。页面 MUST NOT 为填充留白强制提供副标题。费用口径、权限限制、配置作用范围、不可逆后果与真实错误说明 MUST 保留；中英文 MUST 遵循相同约束。

#### Scenario: 标题已经充分表达页面用途

- **WHEN** 页面名称与主要操作已能说明用途，且没有额外业务约束需要说明
- **THEN** 页面不添加“清晰的信息层级”“高效管理体验”或“此区域展示”等填充文案

#### Scenario: 关键业务说明仍然可见

- **WHEN** 新密钥只显示一次、配置仅影响后续请求或权限限制某项操作
- **THEN** 界面明确表达该事实与可执行操作，不因追求简洁而移除必要提示

#### Scenario: 空数据与开发占位区分

- **WHEN** 用户没有密钥或筛选无匹配记录
- **THEN** 界面说明真实空数据原因并在适用时提供创建或清除筛选操作，不显示“设计占位”“示例布局”或产品宣传语

### Requirement: 异步状态必须如实且局部反馈

系统 MUST 区分初次加载、已有数据刷新、真实零值、首次无数据、筛选无结果、加载失败与权限拒绝。请求失败 MUST NOT 被展示为零值、空列表或成功；刷新时保留的旧数据 MUST 有刷新中或刷新失败提示。独立区块部分失败 MUST 在其作用范围内呈现错误；没有成功响应的数据 MUST NOT 冒充真实统计值。

#### Scenario: 个人概览加载失败

- **WHEN** 个人概览请求失败且没有已成功加载的数据
- **THEN** 指标区显示错误和可行的重试入口，不以 0 请求、0 费用表示失败

#### Scenario: 已有列表刷新失败

- **WHEN** 用户在已有列表上刷新而请求失败
- **THEN** 界面保留可用的旧内容并明确提示刷新失败，不清空成“无记录”，且不清除用户的筛选条件

#### Scenario: 无数据与无匹配结果

- **WHEN** 列表成功返回空结果
- **THEN** 无筛选时显示无数据状态，有筛选时显示无匹配结果并提供修改或清除筛选的入口

#### Scenario: 部分统计不可用

- **WHEN** 列表成功加载而对应统计区失败
- **THEN** 列表仍可使用，统计区显示自身错误，不将其解释为全页无数据

### Requirement: 页面密度必须服务内容与设备

系统 MUST 根据概览、密集列表、长配置与短表单的内容选择布局，统一相同控件的语义与反馈，MUST NOT 以同一大卡片布局强制承载全部页面。移动端 MUST 保留主要对象、关键状态、主要操作与详情访问；主要操作 MUST NOT 被固定导航遮挡。高密度内容 MUST 保持可读字号，不通过不断缩小文字解决溢出。

#### Scenario: 在手机查看日志

- **WHEN** 用户在窄视口打开请求记录
- **THEN** 时间、模型、结果及关键用量信息可读，剩余诊断可通过展开查看，筛选与详情仍可操作

#### Scenario: 查看复杂上游配置

- **WHEN** 用户打开上游详情
- **THEN** 用户能识别当前对象、配置分区及每次保存的作用范围，长配置不会退化为没有分组的字段堆积

#### Scenario: 修改密码

- **WHEN** 用户在大屏打开密码表单
- **THEN** 输入区保持适合阅读的宽度，不因大屏而拉满整页或增加无业务作用的旁栏

### Requirement: 重构必须保留业务和跨页契约

系统 MUST 保留现有路由、认证方式、角色隔离、字段与操作能力、统计口径、服务端权限、额度收紧规则、上游可见性与密钥一次性展示。已有深链接的查询参数、对象标识及导航返回语义 MUST 保持有效。列表至详情的返回 MUST 保留现有可恢复的筛选与滚动行为；重构 MUST NOT 无依据增加新指标、价格或成功状态，也 MUST NOT 将分区保存改为整体保存。

#### Scenario: 管理员与成员共享日志展示

- **WHEN** 管理员查看全局日志而成员查看个人请求
- **THEN** 两者展示规则一致且继续使用各自的数据作用域，成员不获得管理员录制或其他受限信息

#### Scenario: 既有下钻链接继续生效

- **WHEN** 用户从排行榜或用户用量详情打开已有的关联请求入口
- **THEN** 请求页面保留链接约定的对象与时间条件，返回行为不因布局调整丢失已有上下文

#### Scenario: 管理限制仍被解释

- **WHEN** 成员密钥被管理员禁用，或管理员尝试触发最后一个启用管理员的保护规则
- **THEN** 现有禁止操作与对应解释保持有效，界面重构不放宽限制

#### Scenario: 分区保存失败

- **WHEN** 用户保存某配置分区失败
- **THEN** 该分区保留编辑内容和错误，其他分区不被隐式提交或重置

### Requirement: 全量交付必须有视觉与行为证据

系统 MUST 在所有目标路由、两种角色和关联交互上通过验收。每页 MUST 有桌面与移动端实际视觉检查；两套主题与两种语言 MUST 检查可读性、长文案和布局，代表性的交互 MUST 检查键盘焦点与减少动态效果。状态验收 MUST 覆盖该页实际存在的正常、加载、空数据、失败与权限限制，不要求不存在的状态。截图自动通过 MUST NOT 替代人工查看实际渲染结果。

#### Scenario: 整体完成判定

- **WHEN** 准备完成本变更
- **THEN** 全部页面及关键接入、资源管理、请求排查和系统操作流程均已验证，未覆盖的环境或状态被明确记录且不被声称通过

#### Scenario: 共享样式变更

- **WHEN** 公共令牌或组件的修改影响成员区、管理端和公开落地页
- **THEN** 验证这些实际调用方，确认落地页的既有布局和交互没有意外回归

### Requirement: 可感知体验优化必须覆盖实际交互全程

系统 MUST 在 P01–P21 的实际页面和关联操作中覆盖以下触点：控件悬停／按压／焦点／选择与禁用；输入与校验；菜单／提示／选择器等浮层；展开收起；导航、返回与滚动；页内、主题与语言切换；加载、刷新与错误恢复；列表筛选、分页、增删及重排；图表与实时变化；保存、复制、测试、文件等操作结果；现有拖拽排序；触屏、键盘、视口与软键盘适配。上述清单 MUST 按实际可达交互核对，发现清单未命名的同类可感知断点 MUST 纳入相应页面，MUST NOT 仅实现用户举例的展开收起和页面切换。已有顺畅体验 MUST 经验证后保留；不适用项 MUST 有具体理由，MUST NOT 为覆盖而新增无业务需求的交互或装饰动画。

#### Scenario: 页面体验完成判定

- **WHEN** 任一页面被标记为完成
- **THEN** 其可达控件、关联操作及等待／结果状态均已检查，每类实际触点有已优化或经验证保留的结论，不以两个示例交互通过代替整页验收

### Requirement: 控件与输入反馈必须及时稳定

系统 MUST 让可操作、按下、聚焦、选中、禁用与处理中状态可辨识；鼠标、键盘和触屏 MUST 能完成相同核心操作，必要信息 MUST NOT 仅依赖悬停。输入与校验反馈 MUST 不丢字、不抢走输入焦点、不因提示出现而无序挤动操作区。处理中文输入法、粘贴、密码显隐和快速操作时 MUST 保持编辑意图。过渡 MUST NOT 使按钮点击区域漂移或延迟业务提交；保存失败 MUST 保留用户输入。

#### Scenario: 输入期间刷新或校验

- **WHEN** 用户输入搜索或表单内容，同时发生刷新、校验提示或密码显隐切换
- **THEN** 输入值、有效选择与焦点保持正确，结果区反馈与输入操作解耦，不重置文本或把未确认的输入法内容当成最终值

#### Scenario: 通过键盘与触屏操作

- **WHEN** 用户使用 Tab、Enter、Escape 或触屏访问按钮、菜单和选择器
- **THEN** 当前焦点与选择可辨识，核心说明与操作可达，不依赖 hover 或只显示不可操作的图标

### Requirement: 浮层与偏好切换必须在不同入口一致

系统 MUST 统一菜单、提示、选择器、日期面板、弹窗的开关节奏与层级，保持触发来源、键盘导航、关闭焦点和边缘避让正确；交互中的浮层 MUST NOT 被父容器裁切或固定导航遮挡。主题／语言切换 MUST 在侧栏、设置和移动账户菜单等实际入口呈现一致反馈，保留已有路由参数与账户状态；主题更新 MUST NOT 引起强闪烁或遗留遮罩。

#### Scenario: 不同入口切换同一偏好

- **WHEN** 用户分别从设置、侧栏或移动账户菜单切换主题或语言
- **THEN** 反馈和最终偏好一致，当前路由参数保留，不因入口不同出现一处平滑一处硬闪的行为

#### Scenario: 边缘浮层和嵌套操作

- **WHEN** 用户在视口边缘或弹窗内部打开菜单、选择器或日期面板
- **THEN** 内容可读可操作，关闭后焦点回到正确来源，背景不会错误滚动或接受被遮挡的点击

### Requirement: 数据变化与结果反馈必须维持阅读上下文

系统 MUST 对筛选、分页、刷新、增删、排序及图表／实时更新给出与实际状态一致的反馈。等待期间保留的旧数据 MUST 不被误认为新条件的结果；结果到达或局部行变化 MUST 保持对象身份和合理的阅读位置，MUST NOT 因动效重播整张列表或抢走焦点。图表变化 MUST 保留真实数值、单位与颜色语义，减少动态效果 MUST 覆盖图表自身动画。复制、保存、测试与文件操作 MUST 按实际完成结果反馈，不提前宣布成功、不以无依据的百分比掩盖等待；局部状态与通知 MUST 不冲突或重复堆积。

#### Scenario: 连续筛选与分页

- **WHEN** 用户快速改变筛选或页码而旧数据仍保留在界面
- **THEN** 输入和目标条件即时响应，旧结果被标识为更新中，最终呈现最新条件的真实结果，失败不伪装为空数据

#### Scenario: 实时更新中阅读详情

- **WHEN** 用户正在阅读或编辑某对象，列表或图表收到新数据
- **THEN** 内容更新不跳到其他对象、不强制滚动或重播整页，所见数值与单位仍真实，关闭动效后更新仍可理解

#### Scenario: 复制或保存失败

- **WHEN** 复制、保存或文件操作未成功
- **THEN** 控件与通知不显示成功状态；可恢复操作保持可重试，输入或上下文不因失败丢失

### Requirement: 既有排序与移动操作必须可完成且有落点反馈

系统 MUST 为既有拖拽排序呈现来源、目标位置与落位结果，取消时恢复正确状态，并提供可由键盘与触屏完成相同排序的非拖拽操作。视口改变、软键盘打开或固定导航存在时，用户 MUST 能访问当前输入和提交／取消操作；页面 MUST NOT 通过抢夺滚动、仅依赖鼠标拖拽或缩小点击区域处理空间不足。

#### Scenario: 排序来源列表

- **WHEN** 用户拖拽请求头补偿的来源项，或使用非拖拽排序控件
- **THEN** 目标位置与最终顺序可辨识，取消不提交错误顺序，两种方式保持相同业务顺序语义

#### Scenario: 手机编辑长表单

- **WHEN** 软键盘出现、视口变矮或用户切换方向
- **THEN** 当前输入和提交／取消可通过正常滚动到达，浮层不被底栏或键盘永久遮挡
