# Spec Delta

## Purpose

管理员可按 CLIProxyAPI 认证账号读取供应商当前的额度窗口、剩余比例和重置时间，并清楚地区分这些实时额度与代理进程内的请求统计及被动配额观测。

## ADDED Requirements

### Requirement: 供应商额度的只读查询

系统 SHALL 提供仅管理员可访问的单账号供应商额度查询。对受支持的 Codex 与 Claude OAuth 账号，系统 SHALL 使用该实例管理连接查询供应商额度，并仅返回供应商类型、读取时间、额度窗口的剩余比例与重置时间。系统 MUST NOT 返回认证索引、Token、原始认证文件或供应商原始响应；MUST NOT 消费请求用量队列、修改账号或写入本地数据库。

#### Scenario: Codex 额度窗口
- **WHEN** 管理员查询具有有效认证索引的 Codex 账号，供应商返回五小时与周额度窗口
- **THEN** 系统按账号返回各窗口的剩余百分比和重置时间，零剩余额度显示为零

#### Scenario: Claude 额度窗口
- **WHEN** 管理员查询具有有效认证索引的 Claude OAuth 账号，供应商返回五小时与七天窗口
- **THEN** 系统按账号返回已提供的窗口及剩余百分比，不推断供应商未返回的窗口

#### Scenario: 鉴权、账号与上游失败
- **WHEN** 非管理员、缺失账号、缺少认证索引或供应商额度请求失败
- **THEN** 系统返回可区分的状态，不泄露管理密钥、账号令牌或原始供应商响应

#### Scenario: 不支持的账号
- **WHEN** 账号的服务商暂无可靠的额度读取方式或账号已停用
- **THEN** 系统不发起供应商请求，并明确说明该账号无法查询实时额度

### Requirement: 额度入口与含义

系统 SHALL 在 CLIProxyAPI 账号行及账号详情中提供可辨认的供应商额度入口。仅在打开指定账号时查询该账号；界面 MUST 展示加载、剩余百分比、重置时间、空数据、失败与刷新状态，并明确区分现有的请求计数和被动配额观测。桌面及窄屏 MUST 可访问此入口且不产生页面级水平溢出。

#### Scenario: 打开并刷新额度
- **WHEN** 管理员打开受支持账号的详情或额度入口
- **THEN** 界面查询并展示该账号额度，允许单独刷新，不影响账号管理或请求统计

#### Scenario: 暂无可用额度窗口
- **WHEN** 查询成功但供应商没有返回可识别的额度窗口
- **THEN** 界面说明当前无可用额度数据，不把未知值显示为零

#### Scenario: 额度查询失败
- **WHEN** 查询失败或刷新失败
- **THEN** 界面显示明确的失败与重试状态，已有账号资料和请求统计保持可用
