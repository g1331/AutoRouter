## ADDED Requirements

### Requirement: 成员上游可见性按用户配置

系统 SHALL 为每个用户持久化一个「上游可见性」布尔属性（`users.expose_upstreams`），默认值 MUST 为隐藏（`false`）。该属性仅影响对应成员侧（`/api/user/*` 与门户 UI）的上游信息暴露，管理端行为 MUST 不受影响。系统 SHALL 提供仅管理员可用的写入口：单用户（`PUT /api/admin/users/{id}` 携带 `expose_upstreams`）与批量（`PATCH /api/admin/users/upstream-visibility`，可对指定用户集或全体成员一次性设置）。非管理员访问上述写入口 MUST 被拒绝。

#### Scenario: 新用户默认隐藏

- **WHEN** 管理员创建新用户
- **THEN** 该用户的上游可见性为隐藏，成员登录后看不到任何上游身份

#### Scenario: 管理员为单个用户切换可见性

- **WHEN** 管理员通过 PATCH 修改某用户的 `expose_upstreams`
- **THEN** 系统持久化新值，该成员后续请求立即按新值分支

#### Scenario: 批量设置可见性

- **WHEN** 管理员对全体成员（或指定用户集）批量设置为隐藏
- **THEN** 所有目标成员的可见性被置为隐藏，且各自名下密钥被重对齐到其授权全集

#### Scenario: 非管理员访问被拒

- **WHEN** member 用户或未认证请求访问可见性写入口
- **THEN** 系统返回 403 或 401

### Requirement: 隐藏态用户的密钥与授权集自动对齐

某用户可见性为隐藏时，其名下的成员自助密钥的可路由上游集合 MUST 与该用户当前的授权集（user_upstreams）保持一致，由服务端在写路径上物化维护：该用户创建密钥时 MUST 绑定当前授权全集；管理员替换该用户授权集时 MUST 同步该用户名下全部密钥的上游集合为新授权集；该用户可见性由可见切换为隐藏（无论单用户还是批量）时 MUST 一次性将其名下密钥重对齐到授权全集。代理路由路径 MUST NOT 因可见性引入额外分支。

#### Scenario: 管理员调整授权后密钥跟随

- **WHEN** 某隐藏态用户的授权集从 {A,B} 改为 {A,C}
- **THEN** 该用户名下所有自助密钥的上游集合变为 {A,C}，后续请求只会路由到 A 或 C

#### Scenario: 切换到隐藏时全量对齐

- **WHEN** 管理员把某用户（或批量把多个用户）从可见切换为隐藏
- **THEN** 这些用户名下密钥的上游集合被重设为各自用户的授权全集

#### Scenario: 空授权集拒绝建键

- **WHEN** 隐藏态且授权集为空的成员尝试创建自助密钥
- **THEN** 系统拒绝创建并返回明确错误

### Requirement: 收回授权同时收回密钥上的该上游

无论某成员的可见性为何，管理员替换该成员的授权集时，系统 MUST 从该成员名下密钥的可路由上游集合中移除已被收回的上游；可见态下成员自选的其余上游 MUST 保留。授权集替换与密钥收敛 MUST 在同一事务内完成。非成员角色名下的密钥与无归属密钥 MUST NOT 受影响。

#### Scenario: 可见态下收回授权

- **WHEN** 某可见态成员密钥的上游集合为 {A,B}，管理员把该成员授权集从 {A,B} 改为 {A,C}
- **THEN** 该密钥的上游集合变为 {A}：B 立即不可再路由，且不会被自动加上未选择的 C

#### Scenario: 无归属密钥不受影响

- **WHEN** 管理员替换某成员的授权集
- **THEN** `user_id` 为空的密钥与管理员名下密钥的上游集合保持不变
